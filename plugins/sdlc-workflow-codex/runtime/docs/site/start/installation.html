Installation

This page shows how to install the sdlc-workflow plugin into Claude Code and what happens in your first session. Two quick checks confirm that the plugin runs.

What you need first

The plugin runs inside Claude Code. Its background work (the hub daemon, the render pipeline, and the hooks) uses Node.js. Claude Code already requires Node.js, so there is nothing extra to install. The one real precondition is git: the plugin registers each project by its git identity, and workflow branches live in git. If you run /wf in a directory that is not a git repository, the command stops and explains why. The command then offers to run git init for you. The plugin never initializes a repository without asking.

Install the plugin

The plugin is distributed through a marketplace hosted in the jayteealao/agent-skills GitHub repository. Inside Claude Code, add the marketplace:

/plugin marketplace add jayteealao/agent-skills

Then install the plugin from it:

/plugin install sdlc-workflow@agent-skills-marketplace

When the install completes, start a fresh session in the project where you want to use the plugin. In that first session, the plugin configures itself.

What happens on the first session

The plugin ships hooks that Claude Code runs automatically at the start of every session. All hooks run in the background. None of them injects anything into your conversation. On a healthy install, none of them needs your attention. Three things happen:

The hub starts. The hub is a single machine-wide daemon on 127.0.0.1:4173, and it registers your repository. The hub serves a rendered, browsable HTML view of every workflow artifact the plugin writes. Each repository gets a dashboard, and the dashboard reloads live as artifacts change. One hub serves every registered repository on your machine. When you install into a second project, the plugin registers that project with the same hub.

The render bootstrap runs. The session-start hook enqueues a whole-repo render of the dashboard, and the hub drains that queue in the background. From then on, the hub renders every workflow artifact that a session writes.

Your instruction files get a rules block. The plugin seeds a small fenced block of /wf usage rules into AGENTS.md at your project root. It also seeds an @AGENTS.md import into CLAUDE.md. The working conventions then travel with the repository. The plugin owns only its own fenced block. The rest of both files is yours. The seeding is fail-open: if anything goes wrong, the plugin does nothing rather than break your session.

You can turn off individual pieces of this behavior. SDLC_DISABLE_BOOTSTRAP=1 skips the render bootstrap, and SDLC_DISABLE_MEMORY_SEED=1 skips the rules seeding. The full list of switches is in Configuration.

Confirm that the plugin runs

Make two checks: one inside Claude Code and one in your browser. First, run the command with no arguments:

/wf

The command must show a menu of all 22 keys: the ten lifecycle stages plus the standalone commands. The command then asks which key you want. If you see that menu, the plugin is installed and dispatches correctly.

Second, open the hub in your browser:

http://127.0.0.1:4173

The dashboard must list your registered repository. The hub also exposes a plain health endpoint at http://127.0.0.1:4173/__sdlc/health. The endpoint is useful for scripts, or for a quick check from the terminal that the hub is up.

A brand-new project shows an empty dashboard, because there are no workflows to render yet. That is normal. The dashboard fills in when your first /wf intake writes its artifacts.

Optional: the tray app

On desktop machines, you can run a small notification-area app that watches the hub for you. The icon and tooltip of the tray app show hub health. The tray app polls the hub every five seconds. The tray menu opens the dashboard, opens per-repository views, and restarts or stops the hub. The tray menu also offers a start-at-login toggle, so the tray app starts again after a reboot.

You launch the tray app yourself, outside Claude Code. From the plugin's installed directory, start the tray app with:

npm run tray

That command runs node dist/tray.mjs, so you can also invoke the file directly. When you enable Start at login from the tray menu, you never need to launch the tray app by hand again. On Windows, the session-start hook also keeps an enabled autostart entry pointed at the current plugin version across upgrades.
