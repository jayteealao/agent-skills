Hooks

This page is the lookup reference for the eight hooks the plugin installs. For each hook, the page lists the event the hook fires on, what the hook does, whether the hook blocks or only warns, and the switch that turns the hook off.

Hooks are how the plugin enforces its contracts automatically, so neither you nor the model has to remember them. Two hooks run at session start. Three hooks run before a tool call — two before a write, one before a shell command — and can block the tool call. Three hooks run after a write: they validate, stage, and render the written files. All hooks are fail-open by design: an internal error in a hook never breaks your session. No hook fires during plugin installation or inside a dispatched read-only sub-agent.

session-start-orient

SessionStart. This hook is pure background maintenance. It produces no chat output and never blocks. When a session starts in a registered repo, the hook starts three detached jobs:

  • Render bootstrap. A background pass renders workflow-view pages that are missing or stale, so the dashboard is current when you open it. The view.bootstrap.* config keys govern the pass. Under SDLC_DISABLE_BOOTSTRAP=1, the pass is skipped entirely.
  • Hub ensure. If the machine-wide hub is not already running, the hook starts the hub. The hook then registers the repo with the hub, unless the repo opted out with view.hub.enabled: false.
  • Tray reconcile (Windows). The hook re-stamps the tray autostart launcher to point at the current plugin version. After an upgrade, the hook also reconciles a tray that is already running on a prior version's code. The hook never creates a launcher and never relaunches a tray you did not opt into. Under SDLC_DISABLE_TRAY_HEAL=1, the running-tray reconcile is skipped.

Everything here is fail-open: session orientation must never break on a rendering or tray problem.

seed-memory

SessionStart. This hook makes sure that a small, versioned, fenced /wf rules block exists in the repo's AGENTS.md. It also makes sure that an @AGENTS.md import line exists in CLAUDE.md, so both hosts read the same kernel. The plugin owns exactly the fenced region: it replaces an older kernel version in place and never touches a byte outside the fence. Seeding runs only in sdlc-engaged repos (repos with a .ai/workflows/ directory). The hook announces itself once, on the first insert, then runs silently. It never blocks.

To disable this hook per repo, set memory.seedRules: false in .ai/sdlc-config.json. To disable it per machine or session, set SDLC_DISABLE_MEMORY_SEED=1. Existing seeded blocks are left untouched either way.

pre-write-validate

PreToolUse, matcher Write. This hook is the gatekeeper for workflow artifacts. It inspects any Write that targets markdown under .ai/workflows/ before the file lands. When the content violates the artifact contract, the hook blocks the write (exit 2, with the reason on stderr). The hook enforces:

  • The filename convention: NN-name.md / NNx-name.md (for example 01-intake.md, 02b-design.md), plus the named exceptions risk-register.md, estimate.md, announce.md, and skip-*.md records.
  • YAML frontmatter with schema, type, and slug keys, and schema: sdlc/v1 exactly.
  • That the frontmatter slug matches the .ai/workflows/<slug>/ directory that receives the file.

The free-form po-answers.md decision log is exempt. That log is prose, not a managed artifact. A missing registry (.ai/workflows/INDEX.md), or a missing slug row in the registry, produces a warning, not a block. To disable this hook, set hooks.validateOnWrite: false.

leak-guard-write

PreToolUse, matcher Write|Edit|MultiEdit. This hook is the External Output Boundary guard for documentation. When a write targets a public documentation path (README*, CHANGELOG*, CONTRIBUTING*, or anything under a docs/ directory outside the internal roots), the hook scans the written content against a lexicon of internal workflow vocabulary. Internal paths (.ai/**, .claude/**) are never scanned. Workflow vocabulary belongs there.

This guard is off by default (semantic.enabled: false). When the guard is enabled, semantic.mode decides the consequence. "advisory" (the default mode) emits a non-blocking message that names the matched vocabulary. "enforce" denies the write. Run advisory first. Promote to enforce only when the false-positive rate in your repo proves near zero.

leak-guard-bash

PreToolUse, matcher Bash. This hook is the same boundary guard, aimed at publishing commands. It scans only the outward-facing text arguments: git commit and git tag messages, and gh pr create / gh release create|edit titles, bodies, and notes (including heredoc bodies). The hook never scans the whole command line, so reading internal files with cat or grep can never trigger the guard. The configuration is the same as the write guard: off by default via semantic.enabled, advisory or enforce via semantic.mode. Body-file flags (-F, --body-file) are not read. Only the path itself is scanned as text.

post-write-auto-stage

PostToolUse, matcher Write|Edit|MultiEdit|NotebookEdit. This hook keeps implementation work staged as it happens. When an active workflow is in the implement stage with a dedicated or shared branch strategy, the hook runs git add on each written implementation file. Workflow artifact files are deliberately skipped: the implement stage's own commits own those files. The hook always exits 0 and never blocks anything.

To disable this hook, set hooks.autoStage: false. For an ad-hoc pause without a config change, drop a .ai/.no-auto-stage marker file.

post-write-verify

PostToolUse, matcher Write|Edit|MultiEdit|NotebookEdit. This hook is the deep validator. It runs after a workflow artifact lands (markdown under .ai/workflows/, .ai/simplify/, and .ai/profiles/; po-answers.md is exempt) and carries most of the plugin's integrity checks. Some checks hard-block (exit 2; the model must fix the artifact before it proceeds). The rest warn without blocking. To disable this hook, set the master switch hooks.verifyOnWrite: false. Each check also has its own key, and all keys default to on (see the configuration reference).

The blocking checks:

  • Deep frontmatter schema validation against the artifact schema: the full check beyond what the pre-write gate enforced.
  • Sibling-fragment enforcement (hooks.remindMissingFragments): a rich-tier artifact .md written without its mandatory sibling .yaml blocks. A missing .html.fragment only nudges. Without the sibling, the workflow view renders that page as plain prose. The per-artifact opt-out is fragment: none in frontmatter.
  • Sibling-YAML schema validation (hooks.validateSiblingYaml): a present sibling .yaml is validated against its per-type schema, for the reconciled types (plan, review, design, simplify-run, ship-run).
  • The verify result gate (hooks.verifyResultGate): a verify artifact that claims result: pass while acceptance criteria are unmet, or while interactive verification is deferred, is a contradiction and blocks.
  • The mock-evidence gate (hooks.mockEvidenceGate): result: pass while a user-observable acceptance criterion's best evidence is a mock or static analysis blocks. Such a criterion is not met. Produce runtime evidence or record a deferral.

The warning-only lints are heuristic and never block:

  • The deferral lint warns when shadow-deferral vocabulary co-occurs with a passing verify result.
  • The limitation-claim lint warns when a comment asserts a dependency limitation with no citation nearby.
  • The suppression-debt lint warns when a new type/lint suppression has no sdlc-debt: marker.
  • The named-mechanism lint warns when an acceptance criterion names a mechanism the design never decided on.
  • The intake-ledger lint warns when a default-mode intake lands with neither ledger entries nor the explicit none-declared escapes.

post-write-render

PostToolUse, matcher Write|Edit|MultiEdit|NotebookEdit. This hook is the bridge from artifact writes to the rendered workflow view. It filters to managed artifact paths (.ai/workflows/, .ai/simplify/, .ai/profiles/, .ai/dep-updates/, .ai/ideation/, docs-run indexes, PRODUCT.md / DESIGN.md, and .ai/ship-plan.md). It debounces bursts of writes with a two-second touch file. It then dispatches a render according to view.renderDispatch:

  • "hub" (the default): the change is enqueued to the durable per-repo render queue (.ai/_view/.render-queue/), and the hub daemon drains and renders it. If no daemon answers and view.ensureHubOnWrite is on, the hook makes a best-effort detached attempt to start the hub.
  • "inline": the legacy path. The hook spawns the renderer itself.

Render errors land in .ai/_view/.render-errors.log. The hook always exits 0, so a stale view can never block a command. The hook suppresses itself in three cases: when the touched path is inside .ai/_view/ (this avoids render-write loops), when a .ai/_view/.render-suppress marker file exists (a per-project pause), and during plugin installation.

The rendered output under .ai/_view/ is machine-owned; hand edits are lost on the next render. When a view looks stale, the hub's self-heal usually catches the drift. When the self-heal does not catch the drift, the render error log above holds the first clue.
