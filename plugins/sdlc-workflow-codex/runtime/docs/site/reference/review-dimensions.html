Review dimensions

This page lists all 35 review dimensions, the 7 sweep aggregates that bundle them, and the rules for ad-hoc invocation. Use this page to pick the right rubric for the review you want.

Invocation and scope

Review has two modes, and the first token tells them apart. /wf review <slug> is the workflow stage: it dispatches one reviewer per selected dimension and merges findings into the accumulating ledger (07-review[-<slice>].md plus one file per dimension). Without a slug, /wf review <dimension> runs one rubric inline, and /wf review sweep <aggregate> fans out one reviewer per bundled dimension. These slug-less runs are the ad-hoc path. Ad-hoc runs write no artifact. Findings return inline in chat, with a verdict and severity counts.

Ad-hoc review runs over one of five scopes, parsed from the remaining tokens:

ScopeTarget
pra PR URL or number
worktreethe uncommitted working-tree changes
diffa commit range
filea file path
repothe whole repository (also the bare default)

To reach a dimension whose name is also a real workflow slug, invoke /wf review sweep <name>, or run the dimension in a repo without that slug.

When a dimension name is also a real workflow slug, the slug wins and the stage runs.

The 35 dimensions

Each dimension is one rubric file that the reviewer follows. Each entry below describes one rubric:

accessibility
Reviews UI changes for keyboard and assistive-technology usability, and for ARIA misuse.
api-contracts
Reviews API contracts for stability, correctness, and usability for consumers.
architecture
Reviews for architectural issues: boundaries, dependencies, and layering.
backend-concurrency
Reviews backend code for race conditions, atomicity violations, locking issues, and idempotency bugs.
ci
Reviews CI/CD pipelines for security, correctness, and deployment safety.
code-simplification
Reviews through the three simplification lenses: missed reuse, quality issues, and inefficiencies.
correctness
Reviews for logic flaws, broken invariants, and edge-case failures.
cost
Reviews for changes that increase cloud infrastructure costs.
data-integrity
Reviews whether stored data stays correct over time, across failures, retries, and concurrent writes.
docs
Reviews documentation completeness and accuracy for behavior, config, and API changes.
dx
Reviews developer experience: whether the project is easy to build, run, debug, and contribute to.
frontend-accessibility
Reviews for accessibility issues specific to modern SPAs (React, Vue, Angular).
frontend-performance
Reviews bundle size, rendering efficiency, and user-perceived latency in frontend changes.
infra
Reviews infrastructure and deployment config for safety, least privilege, and operational clarity.
infra-security
Reviews infrastructure code for security issues: IAM, networking, secrets, and configuration.
intent-fidelity
Reviews whether the diff advances the intake's product or a simplified imitation of it. This code-to-intake fidelity is the thing every other dimension misses.
interface-craft
Reviews the static visual detail that makes interfaces feel polished: radii, optical alignment, shadows, tabular numbers, text wrapping, and hit areas.
logging
Reviews logging for secrets exposure, PII leaks, wide-event patterns, and query-optimized observability.
maintainability
Reviews for long-term readability, ease of change, and reduced change amplification.
migrations
Reviews database migrations for safety, compatibility, and operability in production.
motion
Reviews animation and motion code against a high craft bar: easing, timing, interruptibility, GPU performance, and whether the motion should exist at all.
observability
Reviews observability completeness: logs, metrics, tracing, error reporting, alertability, and runbook hooks.
overengineering
Reviews for unnecessary complexity, abstractions, and YAGNI violations.
performance
Reviews for algorithmic and system-level performance issues.
privacy
Reviews data handling: PII collection, storage, transmission, and privacy compliance.
refactor-safety
Reviews refactors for semantic drift: behavior equivalence and the subtle bugs that break it.
release
Reviews for safe shipping: clear versioning, rollout, migration, and rollback plans.
reliability
Reviews failure modes and operational safety under partial outages.
scalability
Reviews behavior under higher load, larger datasets, and more tenants.
security
Reviews for vulnerabilities, insecure defaults, and missing security controls.
ste-compliance
Audits procedural and external-facing text against the controlled-language contract: terminology drift, ambiguous references, non-imperative instructions, and misplaced warnings.
style-consistency
Reviews consistency with existing codebase style and language idioms.
supply-chain
Reviews dependency and build integrity: lockfiles, build scripts, and artifact provenance.
testing
Reviews test quality, coverage, and reliability.
ux-copy
Reviews user-facing text for clarity, consistency, actionability, and helpful error recovery.

The 7 sweep aggregates

A sweep dispatches one reviewer sub-agent per bundled dimension, in parallel. The sweep then dedupes the findings and synthesizes them into a single verdict. Invoke a sweep with /wf review sweep <aggregate>:

AggregateDimensions bundled
allevery dimension (35 reviewers — the broadest and most expensive)
architecturearchitecture, performance, scalability, api-contracts
infrainfra, ci, release, migrations, logging, observability
pre-mergecorrectness, testing, security, refactor-safety, maintainability
quickcorrectness, style-consistency, dx, ux-copy, overengineering
securitysecurity, privacy, infra-security, data-integrity, supply-chain
uxaccessibility, frontend-accessibility, frontend-performance, interface-craft, motion, ux-copy, ste-compliance

Bare name vs sweep. Three names exist as both a dimension and an aggregate: architecture, infra, and security. A bare /wf review architecture runs the single dimension. /wf review sweep architecture runs the four-reviewer aggregate. The same rule holds for the other two names.

What gets written

Remember one distinction. Ad-hoc runs (a dimension or a sweep, with no slug) write no artifact. Their findings, severity counts, and verdict return inline, and they are gone when the chat is gone. Stage runs (/wf review <slug>) write the accumulating review ledger. Re-runs merge and dedupe in place, preserve finding IDs and surfaced-at stamps, and mark findings that a re-run no longer surfaces as resolved. Nothing is ever overwritten or deleted.
