Hosts: Claude Code and Codex

The plugin runs under two hosts from one source tree. This page lists what the two hosts share, what each host spells differently, and the one key that runs on one host only.

Commands on this site are written as /wf …. Under Codex, type $wf … instead. The key and the arguments are the same.

What both hosts share

Both hosts read the same plugin directory. Both hosts load the same skill files, run the same bundled hook policy, adopt the same machine-wide hub, and read and write the same artifacts under .ai/. A workflow that you start under one host resumes under the other host. The artifact format is the contract; the host that wrote an artifact does not matter.

The verification outcome of a write is identical on both hosts. Only the timing of the block differs.

The one host-specific key

/wf yolo runs under Claude Code only. It is built on a background-workflow tool that Codex does not have. Under Codex the key is unknown; use /wf auto, which runs under both hosts. Every other key runs under both hosts.

Where the host differences live

The skill files never name a host tool. Five reference files carry every host difference, and the skill files cite them: skills/wf/reference/_host-invocation.md (invocation spelling, script paths, key availability), _gate-question.md (the question ladder), _subagents.md (dispatch and effort tiers), _timestamp.md (real timestamps), and yolo.md (the reference for the one Claude Code-only key). A test fails the build when a skill file names a host mechanism outside those files.
