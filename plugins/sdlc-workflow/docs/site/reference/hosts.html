Hosts: Claude Code and Codex

The plugin runs under two hosts from one source tree. This page lists what the two hosts share, what each host spells differently, and the one key that runs on one host only.

Commands on this site are written as /wf …. Under Codex, type $wf … instead. Under pi, type /skill:wf …. The key and the arguments are the same.

What every host shares

Every host reads the same plugin directory. Every host loads the same skill files, runs the same bundled hook policy, adopts the same machine-wide hub, and reads and writes the same artifacts under .ai/. A workflow that you start under one host resumes under another host. The artifact format is the contract; the host that wrote an artifact does not matter.

pi has no plugin manifest and no external hooks of its own. The pi-code extension loads the plugin from the Claude Code plugin cache, runs the Claude Code hook wiring with the Claude Code payload, and presents Claude Code's tool names. A pi cell below reads "same as Claude Code" unless it says otherwise. The pi rows are verified against the extension's documentation, not yet against a live session.

The one host-specific key

/wf yolo runs under Claude Code only. It is built on a background-workflow tool that Codex and pi do not have. Under Codex or pi the key is unknown; use /wf auto, which runs under every host. Every other key runs under every host.

Where the host differences live

The skill files never name a host tool. Five reference files carry every host difference, and the skill files cite them: skills/wf/reference/_host-invocation.md (invocation spelling, script paths, key availability), _gate-question.md (the question ladder), _subagents.md (dispatch and effort tiers), _timestamp.md (real timestamps), and yolo.md (the reference for the one Claude Code-only key). A test fails the build when a skill file names a host mechanism outside those files.
