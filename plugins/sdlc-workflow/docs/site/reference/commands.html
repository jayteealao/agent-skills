Commands

This page lists every /wf key: its exact invocation grammar, what it does, and what it writes. Use this page as a lookup table. The guides explain when to use each command.

Commands on this site are written as /wf …. Under Codex, type $wf … instead. The key and the arguments are the same.

The dispatcher

All plugin operations run through one command: /wf <key> [args…]. The first token must be one of the 19 keys on this page. Six sub-keys and the intake modes take the second token. Everything after the first token passes verbatim to that key. The dispatcher itself has this behavior:

  • Empty invocation. /wf with no arguments renders the key menu and asks which operation you want.
  • Unknown key. A first token that is not a known key is an error. The dispatcher never treats the token as a slug or as an intake mode. The dispatcher lists the 19 valid keys and stops. The table under Renamed commands maps every retired command name to its current spelling.
  • Fuzzy slug suggestion. Exactly five keys have this behavior: shape, slice, plan, implement, and verify. For these keys, a slug that matches no row in .ai/workflows/INDEX.md triggers an advisory typo suggestion ("Did you mean <best-match>?"). The suggestion never auto-corrects; you re-invoke with the suggested slug. Every other key resolves its own first token, which can be a PR number, a branch name, a dimension, a mode, or a sub-key. For those keys the suggestion does not fire.
  • Sub-keys. loop goal, loop optimize, loop prototype, status recap, project ship-plan, and project observability each load their own reference directly. /wf loop or /wf project alone lists its sub-keys and asks which one you want.
  • Intake fast path. /wf intake <mode> … with no slug first loads that mode directly, without the intake dispatcher. Every other intake form runs the dispatcher. Because the dispatcher reads command words before slugs, a new workflow cannot take a key, a sub-key, or a mode word as its slug.
  • Git precondition. Before dispatch, /wf confirms that the project is a git repository. If the project is not a git repository, the dispatcher asks whether to run git init. Artifacts still write without git, but the workflow view does not render until the repo is initialized.
  • Chat summary. Every run ends with a compact summary: a verb-first status line, a short narrative paragraph of two or three plain sentences about what the run built or decided, an Artifacts: line that lists the paths written (or none), and a concrete Next: command.

The lifecycle stages

In lifecycle order: intake → shape → slice → plan → implement → verify → review → handoff → ship → retro. When the work needs design, the human-only design stage runs between shape and slice. All of these stages write artifacts into .ai/workflows/<slug>/. Each stage reads the inputs that the Requires table of its reference names, and writes the stage artifact NN-<stage>[-<slice>].md. Since 9.187.0, stages write no explainer (<stem>.explainer.html.fragment). The Writes lines below name the agent files only. See What every stage reads and writes.

/wf intake

/wf intake [slug] [mode] <description>

Intake is the entry point for the whole lifecycle. A plain description runs the default flow: a product-owner interview, a stack fingerprint, and the creation of the workflow. A mode keyword (fix, rca, investigate, discover, audit, hotfix, refactor, update-deps, ideate, brainstorm, adopt, optimize, simplify, task) routes to an alternative entry flow. An existing slug plus a mode keyword attaches the run as a compressed slice. An existing slug plus free text routes to extension, which adds net-new slices. amend, modernize, and close are maintenance modes that require a slug first. The full mode catalog, the resolution order, and the branch conventions are on Intake modes.

Writes: in the default mode, 00-index.md and 01-intake.md; each other mode has its own artifact set (see the modes page).

/wf shape

/wf shape <slug> [focus area]

Shape turns the intake brief into a compact, implementable mini-spec through product-owner questions. The spec records explicit acceptance criteria, edge cases, and the decisions that downstream stages honor. Shape authors the Documentation Plan and the augmentations-needed decision, which plan, implement, and verify later apply. Shape also adjudicates open entries in the intent-risk (RIM) ledger. When ux-impact is not none, a budgeted design round also produces a design brief with a UX intent section.

Writes: 02-shape.md, plus 02b-design.md (the design brief) when ux-impact is not none.

/wf design

/wf design <slug> [move] [instructions]
/wf design <slug> amend [instructions]
/wf design <slug> import <link|path>...
/wf design [slug] audit|critique
/wf design <move> <instructions>
/wf design setup|teach|extract|direction|sync [instructions]

Design is the human-only stage between shape and slice. It runs when intake recorded a ux-impact other than none. With a slug, it makes one board for every changed surface and state of the feature in design/, shows the contact sheet, asks the person to approve, adjust, or stop, and on approve freezes the boards in design/r<N>/ and writes the visual contract. /wf auto pauses at this stage and /wf yolo refuses to start until the design is settled; neither runs it. A slug plus one of the 15 moves (adapt, animate, bolder, clarify, colorize, delight, distill, harden, layout, onboard, optimize, overdrive, polish, quieter, typeset) focuses the stage on that move. amend reopens a confirmed design when a later stage cannot build it as drawn. import turns a design canvas, a claude.ai/design project, a folder, a zip, or image files into boards, then asks the person to confirm. A move without a slug starts a new workflow through intake with the move recorded. audit and critique run the design review dimensions on demand. setup, teach, extract, direction, and sync maintain the project's design record. direction from <board-slug> presents a change of direction that a design brainstorm carried. When a design brainstorm left thoughts for the workflow, the stage presents them again as its starting direction. Slug resolution is exact-match only. See Design.

Writes: the stage writes 02c-craft.md (with canvas, direction-confirmed-by, confirmed-at, and surfaces, plus carried-from and a ## Carried design thoughts section when a brainstorm carried design thoughts); audit/critique with a slug write 07-design-audit.md/07-design-critique.md; the upkeep commands write PRODUCT.md and DESIGN.md at the project root and .ai/design/current.md and .ai/design/direction.md.

/wf slice

/wf slice <slug>

Slice decomposes the shaped spec into thin, independently verifiable vertical slices. When the work needs design, slice maps every slice to the surfaces in the visual contract, or the master index justifies the grouping. This stage also confirms the workflow's review scope, per-slice or slug-wide, one time, so review does not ask again.

Writes: 03-slice.md (master index) plus one 03-slice-<slice-slug>.md per slice.

/wf plan

/wf plan <slug> [slice-slug|all] [review/fix instructions]

Plan creates the per-slice implementation plan with a parallel reuse scan. When you re-invoke plan on an existing plan, the run switches to review-and-fix. With no extra text, the run reviews the plan against the current codebase. With explicit feedback, the run applies a directed fix. With all, the run reviews every existing plan in parallel. Plan also applies shape's augmentation decisions and authors the corresponding add-on artifacts. Plan does not write the visual contract. When the work needs design, plan consumes 02c-craft.md and writes ## Design Components. A write-time hook refuses the plan while a needed design is not settled.

Writes: 04-plan.md (master) plus 04-plan-<slice-slug>.md per planned slice; conditionally 04b-instrument.md, 04c-experiment.md, 05c-benchmark.md.

/wf implement

/wf implement <slug> [slice-slug|reviews]

Implement codes one planned slice, wires the augmentations that shape decided, and records what was built. The record cross-links to the slice definition and the plan. The second argument reviews runs fix-blockers mode instead: the run works through the open blocker findings from review.

Writes: 05-implement-<slice-slug>.md plus updates to the 05-implement.md master.

/wf verify

/wf verify <slug> [slice]

Verify runs tests, lints, and typechecks. It then applies the acceptance-criteria gate: each criterion is checked against user-observable behavior, with captured evidence. Verify owns a single-round, user-gated fix loop and re-checks augmentations, for example a benchmark comparison. Evidence from prior runs is snapshotted, not overwritten, so reviewers can compare runs.

Writes: 06-verify-<slice-slug>.md plus updates to the 06-verify.md master; the raw check output in the evidence report verify-evidence/<slice-slug>/checks.md, with other evidence files in the same folder.

/wf review

/wf review <slug> [slice | triage]     # workflow stage
/wf review <dimension>                 # ad-hoc, one rubric
/wf review sweep <aggregate>           # ad-hoc, parallel fan-out

Review is the single review surface. With a slug, review runs stage 7: one reviewer sub-agent runs per selected dimension, and the findings merge into an accumulating ledger. Re-runs dedupe and merge in place, mark cleared findings resolved, and never overwrite. The stage ends in a verdict of ship, ship-with-caveats, or dont-ship. triage re-triages open and deferred findings. Without a slug, a dimension name or a sweep name runs an ad-hoc review over a chosen scope and returns findings inline. All 35 dimensions, the 7 sweep aggregates, and the disambiguation rules are on Review dimensions.

Writes: in stage mode, 07-review.md (slug-wide) or 07-review-<slice-slug>.md (per-slice) plus one 07-review[-<slice>]-<dimension>.md per dimension run. Ad-hoc runs write nothing.

/wf handoff

/wf handoff <slug|pr#N|branch> [slice-slug]

Handoff aggregates all complete slices of a slug into a PR-ready package with reviewer and QA context. A pr#N or branch-name first argument runs batch mode: the run assesses every slug on the branch, packages ready slugs into the single shared PR, and records the branch-level readiness check on the lead slug. Handoff refuses a slug when a required review has unresolved blockers. Handoff hard-blocks on any open intent-risk (RIM) entry. Handoff also runs the ship-plan readiness pre-check, so a missing or drifted .ai/ship-plan.md surfaces before the PR is declared ship-ready.

Writes: 08-handoff.md per slug (batch mode: one per slug; the lead's frontmatter carries the branch-level readiness keys, and each follower points to it with readiness-via).

/wf ship

/wf ship <slug|pr#N|branch> [environment|announce|rollback] [<run-id>]

Ship runs a release through the project's .ai/ship-plan.md: a 13-step, idempotent, replayable sequence, from pre-flight through merge, tag, workflow watch, and post-release bookkeeping, under a fresh run-id. When you re-run after a partial failure, the run resumes at the failed step. The run refuses to start unless readiness is ready. Batch mode ships every slug on the branch atomically as one run. announce re-runs only the stakeholder-comms phase. rollback runs a runbook-driven, Go/No-Go-gated reversal of a completed run.

Writes: 09-ship-run-<run-id>.md on the lead slug plus a refreshed 09-ship-runs.md per roster slug; rollback writes 09-rollback-<run-id>.md.

/wf retro

/wf retro <slug|pr#N|branch>

Retro is the post-mortem stage. It extracts reusable lessons and turns them into concrete improvements to prompts, hooks, repo instructions, tests, and automation. Batch mode retrospects every slug on the branch, one retro each, and skips slugs with nothing to retro. Batch mode also synthesizes the cross-slug lessons that span the whole branch.

Writes: 10-retro.md (one per slug in batch mode).

Four intake forms in detail

These intake forms have a section of their own. The other modes are on Intake modes.

/wf intake brainstorm

/wf intake brainstorm <idea>
/wf intake brainstorm design <idea>
/wf intake brainstorm <brainstorm-slug> [design]
/wf intake brainstorm <brainstorm-slug> add <text>
/wf intake <feature-slug> brainstorm design [idea]
/wf intake <feature-slug> brainstorm <topic>

Brainstorm thinks an idea through with you, as a loop of question batches on a board that stays open until you say done. design focuses the brainstorm on how the idea looks and behaves. The design focus reads the design record, maps the design space, and draws rough sketches: on the design canvas, else as an HTML sketch or an /imagery image, else as a one-sentence scene. Each sketch is also saved in design/sketches/ of the workflow. A sketch is an idea only. The brainstorm never writes 02c-craft.md, never resolves the image gate, and never records direction-confirmed-by. The first token resolves by exact existence. A brainstorm slug resumes that board, and design switches its focus. A feature slug with design brainstorms the design of that workflow; done then routes to /wf design <slug>, or to /wf design <slug> amend when the design is already confirmed. A feature slug with any other topic runs a compressed brainstorm slice. At done on a standalone board, each piece of work carries its design items, a proposed ux-impact, and its sketches to the design stage. See Design.

add records one new piece of work on a brainstorm board, for example a bug found while trying built work, and writes its packet.

Writes: a standalone board writes 00-index.md, 01-brainstorm.md, and brainstorm-board.json, keeps its sources in research/ and references/, and at done writes one work packet per piece in work/; a design brainstorm on a feature workflow writes brainstorm-board-design.json and design-notes/brainstorm-design.md beside that workflow's artifacts.

/wf intake simplify

/wf intake simplify [branch [<base>] | commit <sha-or-range> | plan <slug> <slice> | codebase [<path>]]

Simplify is review-and-route triage. Three parallel reviewers (Code Reuse, Code Quality, Efficiency) sweep one of four scopes; the branch diff is the default scope. The reviewers classify what they find and route each finding to the right downstream command. Simplify also harvests sdlc-debt: markers repo-wide. Simplify never writes code directly.

Writes: nothing. Findings are routed, not recorded as an artifact.

/wf intake task

/wf intake task <description | task-slug>
/wf intake <existing-slug> task <description>

Task is the minimal lifecycle for work whose deliverable is not a code change: repo chores, environment and infrastructure operations (rotate a key, set a DNS record), non-code deliverables (an RFC, a license audit), coordination with external parties, and one-shot throwaway execution. Task briefs the work with acceptance criteria that each name how the outcome will be observed, classifies the blast radius (repo-local, local-env, shared-env, external-party, irreversible), and gates before acting: the bottom three classes always stop for explicit human authorization. After executing, task re-observes every outcome — an acceptance criterion whose only evidence is the agent's own claim of success (asserted) cannot close. An existing non-closed slug before task attaches the task as a compressed slice instead.

Writes: 00-index.md, 01-task.md (the brief), 05-implement.md, 06-verify.md; slice mode writes one 03-slice-task-<descriptor>.md with the evidence inline.

/wf intake <slug> close

/wf intake <slug> close [<slice> | reason]

Close terminates a lifecycle. With a reason, or with nothing, close archives the whole workflow at whatever stage the workflow reached and sets status closed. With a slice slug, close closes only that slice, so downstream prerequisites are satisfied. Close never deletes artifacts, PRs, or branches. Close never edits application code.

Writes: 99-close.md for a workflow close; skip-slice-<slice>.md for a slice close.

The other eight keys

The keys below are in alphabetical order. They are runtime verification, drivers, loops, navigation, and routers.

/wf auto

/wf auto <slug> [<slice>]

Auto is the human-gated end-to-end driver. It runs each stage of an already-started workflow in-process. It proceeds on clean terminal states and pauses whenever a stage's own gate fires: an unmet acceptance criterion, an unresolved review blocker, a design that the person has not confirmed, or a pending question. With a slice, auto drives that slice to its end. Without a slice, auto drives every slice and the final review. Auto always stops before handoff. Auto never opens a PR and never fixes CI.

Writes: nothing of its own. The stages it drives write their normal artifacts.

/wf campaign

/wf campaign <slug>

Campaign drives the many workflow slugs that one brainstorm or one ideate pick ended in. The slug is the workflow whose work/index.md lists the packets. It reads the work packets in that workflow's work/ folder and puts them in dependency waves: a wave holds every packet whose dependencies are done, and two packets that touch the same slug never share a wave. The campaign owns the dependency graph in its ledger. The graph starts as a serial chain in the brainstorm's order, and a scout agent proposes the real edges, each with a reason. The person confirms each unit before setup; a unit without confirmation never joins a wave. The deps command of the campaign script shows, plans, confirms, and changes the graph. Setup asks the person four questions: the forecast, the target version, whether each wave releases, and the outputs to build. The person then prepares each slug (intake, shape, slice, and the design stage when the packet needs one); the campaign never makes an intake or shape decision. Each wave is one run of the wave driver, a Workflow script of its own. The run drives every slug of the wave by the decision policy of /wf yolo. It then merges the slugs into one wave branch, verifies the merge, reviews the merged wave diff, and records what each slug actually built. A slug that stops on a question waits for the person, and the other slugs continue. The campaign then hands off and ships one PR per wave. A slug that breaks the wave verify is found by reverting the merges newest first, and the other slugs stay merged. Before the next wave, a drift check compares what the earlier slugs built with what the next slugs expect. The waves need an isolation contract in .ai/sdlc-config.json (campaign.isolation: ports, build folders, and the test suites that run one at a time). With the contract, up to campaign.width slugs of a wave drive at once, each in its own worktree; with parallel: false, the slugs drive one at a time, still in worktrees. While a wave runs, /wf yolo refuses a slug of that wave and names the campaign. With gh-stack v0.1.0 or later, the wave PRs form a stack, and the next wave starts on the wave branch below while that wave waits in handoff or ship, with at most two unshipped waves. A usage budget, asked at setup, narrows the campaign to one slug at 75% of the 5-hour window and pauses it at 90%; the sdlc mod writes the pause and resumes the campaign when the window resets. Setup and prepare run on every host; the waves run on Claude Code only. The campaign asks the person at every handoff or ship issue. One command resumes at any point.

Writes: work/campaign/ inside the brainstorm: ledger.json (the state), ledger.md, forecast.md, one context file per slug (the stages of the wave driver read it), the wave review record in review/, the as-built notes, the drift and fidelity checks, and one try-it note per wave. Built outputs go to .scratch/campaign/. The campaign never writes the board or a packet.

/wf docs

/wf docs [<primitive> | <slug> | --audit-only | <path>]

Docs is the documentation router. Orchestrator mode (no argument, a slug, a path, or --audit-only) runs the full pipeline: discover existing docs, audit them, plan, generate, and review. Slug mode fulfills the shape's Documentation Plan. Primitive mode (plan, tutorial, how-to, reference, explanation, readme, review) writes a single Diátaxis document in place.

Writes: documentation output at project doc paths; pipeline artifacts under .ai/docs/<run-id>/.

/wf loop <goal|optimize|prototype> …

Loop holds the three loops. Each sub-key loads its own reference. /wf loop alone lists the three and asks which one you want.

/wf loop goal

/wf loop goal <slug> [objective]
/wf loop goal <slug> resume|status|clear

Goal writes a goal contract for one slug and hands it to the host goal, which keeps the work going over many turns. The host carries the turns: its own continuation, pause, and resume. A script decides when the goal is done. goal.mjs check prints the evidence and then one last line: GOAL: MET, GOAL: NOT-MET <reason>, or GOAL: BLOCKED <reason>. The condition that the host's judge reads says to trust only that line, so a claim without output is not evidence. A goal has one of three kinds. lifecycle (the default) is met when the slug is ready for handoff, by the same stop rules as /wf auto. optimize is met when the metric loop of an optimize slug is complete. proofs is met when every named command exits 0. A human gate ends the goal: the agent parks the goal at the gate and never answers the gate itself. You answer the gate, then run /wf loop goal <slug> resume. The script counts its checks and blocks the goal after max-checks (default 30). On Claude Code, the model cannot type the built-in /goal command: on the Desktop app the sdlc mod submits it, and on the CLI the mod puts it into the prompt box for your Enter. On Codex, the model calls the goal tool. pi has no host goal, so the loop runs in the session.

Writes: goal.md (the contract), goal/checks.jsonl (one line per check), and goal/arm.json (the arming request that the mod reads).

/wf loop optimize

/wf loop optimize <slug>
/wf loop optimize <description>

Optimize runs a metric loop on an optimize slug: change the code, measure one number, and keep or revert the change. A description starts a new optimize slug through /wf intake optimize, where you confirm the metric spec: the metric command, its direction, a guard command that must pass after every change, the paths that a trial may change, and the budget. The script optimize.mjs makes every git write, every measurement, and every keep or revert; the agent only proposes and edits. The trials run in a separate worktree, so your own working tree is never reset. The baseline runs the metric several times, and the spread of those runs is the noise floor. A change is kept only when its gain is larger than twice the noise and a confirm run agrees. On a fixed share of the budget, a branch round forks the best code into four fresh branches. Each branch proposer reads only the trials of its own branch, and the best branch becomes the trunk. A plateau opens a round early, and the loop stops on a plateau only when that round finds no gain. This follows the fork-and-flush result of arXiv 2610.07447. When the loop ends, the kept trials are squashed into one commit on the slug branch, as one slice for /wf verify <slug> optimize and /wf review. Review adds a metric-gaming check. The driver runs on Claude Code only; on another host, /wf loop goal <slug> carries the loop, one trial per turn.

Writes: optimize/state.json and optimize/results.jsonl (the ledger) during the loop; 03-slice.md, 03-slice-optimize.md, and 05-implement-optimize.md at the finish.

/wf loop prototype

/wf loop prototype <idea>
/wf loop prototype <slug> [request]

Prototype proves an idea by running code. An idea starts a new prototype: a worktree at <parent>/<repo>.poc/<slug> on the branch poc/<slug>, with the workflow folder inside that worktree. The main checkout gets one row in INDEX.md, so /wf status finds the prototype. A slug plus your request runs one round, and the agent then returns. A round has one kind: research, prove, compare, diagnose, decide, generalize, document, or talk. Every proof gets a card in the ledger with its question, setup, evidence, a repeat run in a fresh process, a verdict, and the licenses of what it used. A measured number and an estimated number never look the same. Only your words start a round, and only a decide round makes a commit: the script stages the accepted files by explicit path and refuses a staged file that the decision does not name. /wf auto, /wf yolo, /wf loop goal, and /wf campaign refuse a prototype slug. exit park, exit graduate, and exit close end a prototype; graduate prints the intake command that carries the accepted pipeline into a real workflow. cleanup removes a closed prototype's worktree and keeps the branch.

Writes: in the worktree, 00-index.md, prototype-ledger.json (the proof cards, rounds, decisions, pipeline, and rejected paths), 01-prototype.md (the accepted pipeline in plain words), and report.html (the rolling report: no script, media embedded, under 1 MB). Run output goes to .scratch/prototype/, which git ignores. The main checkout gets only the INDEX.md row.

/wf probe

/wf probe <slug> [target|sweep]
/wf probe sweep [path]

Probe verifies already-built work against runtime truth. It drives the running artifact, captures observable output, and compares the output against the record. Target mode compares the output against acceptance-criteria text. sweep enumerates the whole user surface and compares the surface against the acceptance criteria, the charter's constraints, and the shared eight-class surface-defect taxonomy. sweep as the first token runs slug-less against any repo. Probe never writes code and never writes fixes.

Writes: a compressed slice 03-slice-probe-<descriptor>.md in the workflow; a slug-less sweep writes the project-level .ai/surface-sweep-<utc-date>.md instead.

/wf project <ship-plan|observability> …

Project holds the two project-level contracts, .ai/ship-plan.md and .ai/observability.md. Each sub-key loads its own reference. /wf project alone lists the two and asks which one you want.

/wf project ship-plan

/wf project ship-plan <init|build|edit|audit> [args]

Ship-plan is the project release-pipeline router. init authors .ai/ship-plan.md, optionally seeded from a template (kotlin-maven-central, npm-public, pypi, container-image, server-deploy, library-internal). build brings the repo and CI into compliance with the plan and supports --dry-run. edit makes block-level amendments and bumps the plan version. audit is a read-only adversarial soundness review across seven lenses (plan-soundness, release-safety, ci-correctness, secrets-and-permissions, supply-chain, rollback-realism, version-integrity). audit routes each finding to its fixer and fixes nothing itself.

Writes: init/edit write .ai/ship-plan.md; build writes the repo/CI files it emits; audit writes only its accumulating ledger .ai/ship-plan-audit.md.

/wf project observability

/wf project observability <init|build|audit> [args]

Observability is the project observability router. init inventories the codebase's current logging, telemetry, and analytics, reads the ship plan, and consultatively authors the project contract. The contract covers schema, sampling, redaction, pipeline, backend, and dashboards, and is language-agnostic. build realizes the contract: emit-layer adapters, collector and pipeline config, backend IaC, and dashboards-as-code. build gates every remote or billable step. audit is a read-only soundness sweep across seven lenses. audit routes findings and fixes nothing. There is no edit sub-key. To change the contract, amend the contract file by hand.

Writes: init writes .ai/observability.md; build writes the config and code it emits; audit writes only its accumulating ledger .ai/observability-audit.md.

/wf status

/wf status [slug|pr#N|branch] [deep]
/wf status advise [branch|pr#N|fast]

Status is the dashboard and the registry keeper. With no argument, status renders the cross-workflow status table. With a slug, status shows the detail view and the exact next command, plus every option from the current stage file's recommended-routes frontmatter (an older artifact without that key gives its options from its ## Recommended Next Stage section). With a PR number or a branch, status shows a read-only roster of every slug on that branch. deep runs a reality-drift check against code, git, and dependencies. advise reasons across all open workflows and renders a ranked cross-slug sequencing plan; the plan is read-only and ephemeral. Every status run first reconciles the registry .ai/workflows/INDEX.md against disk.

Writes: normally nothing beyond the INDEX.md reconciliation; deep writes a 00-sync.md drift report.

/wf status recap

/wf status recap <slug|pr#N|branch> [slice-slug | plan|shape|slice|review|findings]

Recap is a plain-language catch-up. Give recap a slug to hear the story of the whole workflow: what was decided, what was built, what was checked, and where the workflow stands. Give recap a slice to recap only that slice. Give recap a focus token to have one artifact explained. Batch mode recaps every slug on a branch and tells the combined story. Recap reads the frontmatter and the body of each stage file, and its page in the workflow view is the slug's story page. Recap never advances the workflow.

Writes: 90-recap.md.

/wf yolo

/wf yolo <slug> [<slice>]

Yolo is the autonomous sibling of auto (Claude Code only; unavailable under Codex — see Hosts). Where auto pauses at gates, yolo resolves each gate by a written decision policy and records every decision in the artifact trail. Each decision is classified as implementation-detail or intent-bearing. By policy, an intent-bearing auto-resolution is an escape that should have been a stop, and the closing decision digest names each one explicitly for audit. Sub-agents append heartbeats to .driver-journal.jsonl, so a dead driver is distinguishable from a slow driver. Yolo drives plan → implement → verify → review, refuses to start while a needed design is not settled, stops before handoff, and refuses terminal-analysis workflows (including audits) and task workflows — a task's authorization gate is a human gate no written policy may resolve.

Writes: nothing of its own. The stages it drives write their artifacts; heartbeats go to .ai/workflows/<slug>/.driver-journal.jsonl.
