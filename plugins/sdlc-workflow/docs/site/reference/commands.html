Commands

This page lists every /wf key: its exact invocation grammar, what it does, and what it writes. Use this page as a lookup table. The guides explain when to use each command.

The dispatcher

All plugin operations run through one command: /wf <key> [args…]. The first token must be one of the 21 keys on this page. Everything after the first token passes verbatim to that key. The dispatcher itself has this behavior:

  • Empty invocation. /wf with no arguments renders the key menu and asks which operation you want.
  • Unknown key. A first token that is not a known key is an error. The dispatcher never silently treats the token as a slug. The dispatcher lists the 21 valid keys. For a retired command name, the dispatcher names the replacement invocation.
  • Fuzzy slug suggestion. Exactly six keys have this behavior: shape, slice, plan, implement, verify, and close. For these keys, a slug that matches no row in .ai/workflows/INDEX.md triggers an advisory typo suggestion ("Did you mean <best-match>?"). The suggestion never auto-corrects; you re-invoke with the suggested slug. Every other key resolves its own first token, which can be a PR number, a branch name, a dimension, a mode, or a sub-key. For those keys the suggestion does not fire.
  • Git precondition. Before dispatch, /wf confirms that the project is a git repository. If the project is not a git repository, the dispatcher asks whether to run git init. Artifacts still write without git, but the workflow view does not render until the repo is initialized.
  • Chat summary. Every run ends with a compact summary: a verb-first status line, a short narrative paragraph, an Artifacts: line that lists the paths written (or none), and a concrete Next: command.

The ten lifecycle stages

In lifecycle order: intake → shape → slice → plan → implement → verify → review → handoff → ship → retro. All ten write artifacts into .ai/workflows/<slug>/.

/wf intake

/wf intake [slug] [mode] <description>

Intake is the entry point for the whole lifecycle. A plain description runs the default flow: a product-owner interview, a stack fingerprint, and the creation of the workflow. A mode keyword (fix, rca, investigate, discover, hotfix, refactor, update-deps, ideate, adopt) routes to an alternative entry flow. An existing slug plus a mode keyword attaches the run as a compressed slice. An existing slug plus free text routes to extension, which adds net-new slices. amend and modernize are maintenance modes that require a slug. The full mode catalog, the resolution order, and the branch conventions are on Intake modes.

Writes: in the default mode, 00-index.md and 01-intake.md; each other mode has its own artifact set (see the modes page).

/wf shape

/wf shape <slug> [focus area]

Shape turns the intake brief into a compact, implementable mini-spec through product-owner questions. The spec records explicit acceptance criteria, edge cases, and the decisions that downstream stages honor. Shape authors the Documentation Plan and the augmentations-needed decision, which plan, implement, and verify later apply. Shape also adjudicates open entries in the intent-risk (RIM) ledger. When the work has a visual surface, a budgeted design round also produces a design brief.

Writes: 02-shape.md, plus 02b-design.md (the design brief) when the work has UI surface.

/wf slice

/wf slice <slug>

Slice decomposes the shaped spec into thin, independently verifiable vertical slices. When a design brief or a visual contract exists, slice boundaries must reflect its states and surfaces, or the master index must justify the grouping. This stage also confirms the workflow's review scope, per-slice or slug-wide, one time, so review does not ask again.

Writes: 03-slice.md (master index) plus one 03-slice-<slice-slug>.md per slice.

/wf plan

/wf plan <slug> [slice-slug|all] [review/fix instructions]

Plan creates the per-slice implementation plan with a parallel reuse scan. When you re-invoke plan on an existing plan, the run switches to review-and-fix. With no extra text, the run reviews the plan against the current codebase. With explicit feedback, the run applies a directed fix. With all, the run reviews every existing plan in parallel. Plan also applies shape's augmentation decisions and authors the corresponding add-on artifacts. When a design brief exists without a visual contract, plan authors the visual contract.

Writes: 04-plan.md (master) plus 04-plan-<slice-slug>.md per planned slice; conditionally 02c-craft.md (visual contract), 04b-instrument.md, 04c-experiment.md, 05c-benchmark.md.

/wf implement

/wf implement <slug> [slice-slug|reviews]

Implement codes one planned slice, wires the augmentations that shape decided, and records what was built. The record cross-links to the slice definition and the plan. The second argument reviews runs fix-blockers mode instead: the run works through the open blocker findings from review.

Writes: 05-implement-<slice-slug>.md plus updates to the 05-implement.md master.

/wf verify

/wf verify <slug> [slice]

Verify runs tests, lints, and typechecks. It then applies the acceptance-criteria gate: each criterion is checked against user-observable behavior, with captured evidence. Verify owns a single-round, user-gated fix loop and re-checks augmentations, for example a benchmark comparison. Evidence from prior runs is snapshotted, not overwritten, so reviewers can compare runs.

Writes: 06-verify-<slice-slug>.md plus updates to the 06-verify.md master; evidence files under verify-evidence/<slice-slug>/.

/wf review

/wf review <slug> [slice | triage]     # workflow stage
/wf review <dimension>                 # ad-hoc, one rubric
/wf review sweep <aggregate>           # ad-hoc, parallel fan-out

Review is the single review surface. With a slug, review runs stage 7: one reviewer sub-agent runs per selected dimension, and the findings merge into an accumulating ledger. Re-runs dedupe and merge in place, mark cleared findings resolved, and never overwrite. The stage ends in a verdict of ship, ship-with-caveats, or dont-ship. triage re-triages open and deferred findings. Without a slug, a dimension name or a sweep name runs an ad-hoc review over a chosen scope and returns findings inline. All 34 dimensions, the 7 sweep aggregates, and the disambiguation rules are on Review dimensions.

Writes: in stage mode, 07-review.md (slug-wide) or 07-review-<slice-slug>.md (per-slice) plus one 07-review[-<slice>]-<dimension>.md per dimension run. Ad-hoc runs write nothing.

/wf handoff

/wf handoff <slug|pr#N|branch> [slice-slug]

Handoff aggregates all complete slices of a slug into a PR-ready package with reviewer and QA context. A pr#N or branch-name first argument runs batch mode: the run assesses every slug on the branch, packages ready slugs into the single shared PR, and records the branch-level readiness check on the lead slug. Handoff refuses a slug when a required review has unresolved blockers. Handoff hard-blocks on any open intent-risk (RIM) entry. Handoff also runs the ship-plan readiness pre-check, so a missing or drifted .ai/ship-plan.md surfaces before the PR is declared ship-ready.

Writes: 08-handoff.md per slug (batch mode: one per slug, with the readiness block on the lead).

/wf ship

/wf ship <slug|pr#N|branch> [environment|announce|rollback] [<run-id>]

Ship runs a release through the project's .ai/ship-plan.md: a 13-step, idempotent, replayable sequence, from pre-flight through merge, tag, workflow watch, and post-release bookkeeping, under a fresh run-id. When you re-run after a partial failure, the run resumes at the failed step. The run refuses to start unless readiness is ready. Batch mode ships every slug on the branch atomically as one run. announce re-runs only the stakeholder-comms phase. rollback runs a runbook-driven, Go/No-Go-gated reversal of a completed run.

Writes: 09-ship-run-<run-id>.md on the lead slug plus a refreshed 09-ship-runs.md per roster slug; rollback writes 09-rollback-<run-id>.md.

/wf retro

/wf retro <slug|pr#N|branch>

Retro is the post-mortem stage. It extracts reusable lessons and turns them into concrete improvements to prompts, hooks, repo instructions, tests, and automation. Batch mode retrospects every slug on the branch, one retro each, and skips slugs with nothing to retro. Batch mode also synthesizes the cross-slug lessons that span the whole branch.

Writes: 10-retro.md (one per slug in batch mode).

The other eleven keys

The keys below are in alphabetical order. They are standalone commands, drivers, navigation, lifecycle control, and routers.

/wf auto

/wf auto <slug> [<slice>]

Auto is the human-gated end-to-end driver. It runs each stage of an already-started workflow in-process. It proceeds on clean terminal states and pauses whenever a stage's own gate fires: an unmet acceptance criterion, an unresolved review blocker, or a pending question. With a slice, auto drives that slice to its end. Without a slice, auto drives every slice and the final review. Auto always stops before handoff. Auto never opens a PR and never fixes CI.

Writes: nothing of its own. The stages it drives write their normal artifacts.

/wf close

/wf close <slug> [<slice> | reason]

Close terminates a lifecycle. With a reason, or with nothing, close archives the whole workflow at whatever stage the workflow reached and sets status closed. With a slice slug, close closes only that slice, so downstream prerequisites are satisfied. Close never deletes artifacts, PRs, or branches. Close never edits application code.

Writes: 99-close.md for a workflow close; skip-slice-<slice>.md for a slice close.

/wf design

/wf design [slug] <command> [instructions]

Design is the design surface. Its 20 commands are arguments, never keys of their own. Fifteen transformation verbs (animate, bolder, clarify, colorize, delight, distill, harden, layout, onboard, optimize, overdrive, polish, quieter, typeset, adapt) author a focused visual contract and then drive slice → plan → implement → verify themselves. audit and critique write a one-shot design review. extract is a read-only token and style extraction. setup and teach author the project-root context files. Slug resolution is exact-match only. Every design run reports a register (brand or product) and an image-gate line.

Writes: transforms write a focused 02c-craft.md, the build-span artifacts, and a design-notes/<command>-<timestamp>.md change record; audit/critique write 07-design-audit.md/07-design-critique.md; extract writes design-notes/extract-<timestamp>.md + design-notes/tokens-extracted.css; setup/teach write PRODUCT.md/DESIGN.md at the project root.

/wf docs

/wf docs [<primitive> | <slug> | --audit-only | <path>]

Docs is the documentation router. Orchestrator mode (no argument, a slug, a path, or --audit-only) runs the full pipeline: discover existing docs, audit them, plan, generate, and review. Slug mode fulfills the shape's Documentation Plan. Primitive mode (plan, tutorial, how-to, reference, explanation, readme, review) writes a single Diátaxis document in place.

Writes: documentation output at project doc paths; pipeline artifacts under .ai/docs/<run-id>/.

/wf observability

/wf observability <init|build|audit> [args]

Observability is the project observability router. init inventories the codebase's current logging, telemetry, and analytics, reads the ship plan, and consultatively authors the project contract. The contract covers schema, sampling, redaction, pipeline, backend, and dashboards, and is language-agnostic. build realizes the contract: emit-layer adapters, collector and pipeline config, backend IaC, and dashboards-as-code. build gates every remote or billable step. audit is a read-only soundness sweep across seven lenses. audit routes findings and fixes nothing. There is no edit sub-key. To change the contract, amend the contract file by hand.

Writes: init writes .ai/observability.md; build writes the config and code it emits; audit writes only its accumulating ledger .ai/observability-audit.md.

/wf probe

/wf probe <slug> [target|sweep]
/wf probe sweep [path]

Probe verifies already-built work against runtime truth. It drives the running artifact, captures observable output, and compares the output against the record. Target mode compares the output against acceptance-criteria text. sweep enumerates the whole user surface and compares the surface against the acceptance criteria, the charter's constraints, and the shared eight-class surface-defect taxonomy. sweep as the first token runs slug-less against any repo. Probe never writes code and never writes fixes.

Writes: a compressed slice 03-slice-probe-<descriptor>.md in the workflow; a slug-less sweep writes the project-level .ai/surface-sweep-<utc-date>.md instead.

/wf recap

/wf recap <slug|pr#N|branch> [slice-slug | plan|shape|slice|review|findings]

Recap is a plain-language catch-up. Give recap a slug to hear the story of the whole workflow: what was decided, what was built, what was checked, and where the workflow stands. Give recap a slice to recap only that slice. Give recap a focus token to have one artifact explained. Batch mode recaps every slug on a branch and tells the combined story. Recap never advances the workflow.

Writes: 90-recap.md.

/wf ship-plan

/wf ship-plan <init|build|edit|audit> [args]

Ship-plan is the project release-pipeline router. init authors .ai/ship-plan.md, optionally seeded from a template (kotlin-maven-central, npm-public, pypi, container-image, server-deploy, library-internal). build brings the repo and CI into compliance with the plan and supports --dry-run. edit makes block-level amendments and bumps the plan version. audit is a read-only adversarial soundness review across seven lenses (plan-soundness, release-safety, ci-correctness, secrets-and-permissions, supply-chain, rollback-realism, version-integrity). audit routes each finding to its fixer and fixes nothing itself.

Writes: init/edit write .ai/ship-plan.md; build writes the repo/CI files it emits; audit writes only its accumulating ledger .ai/ship-plan-audit.md.

/wf simplify

/wf simplify [branch [<base>] | commit <sha-or-range> | plan <slug> <slice> | codebase [<path>]]

Simplify is review-and-route triage. Three parallel reviewers (Code Reuse, Code Quality, Efficiency) sweep one of four scopes; the branch diff is the default scope. The reviewers classify what they find and route each finding to the right downstream command. Simplify also harvests sdlc-debt: markers repo-wide. Simplify never writes code directly.

Writes: nothing. Findings are routed, not recorded as an artifact.

/wf status

/wf status [slug|pr#N|branch] [deep]
/wf status advise [branch|pr#N|fast]

Status is the dashboard and the registry keeper. With no argument, status renders the cross-workflow status table. With a slug, status shows the detail view and the exact next command. With a PR number or a branch, status shows a read-only roster of every slug on that branch. deep runs a reality-drift check against code, git, and dependencies. advise reasons across all open workflows and renders a ranked cross-slug sequencing plan; the plan is read-only and ephemeral. Every status run first reconciles the registry .ai/workflows/INDEX.md against disk.

Writes: normally nothing beyond the INDEX.md reconciliation; deep writes a 00-sync.md drift report.

/wf yolo

/wf yolo <slug> [<slice>]

Yolo is the autonomous sibling of auto (Claude-only, not in the Codex build). Where auto pauses at gates, yolo resolves each gate by a written decision policy and records every decision in the artifact trail. Each decision is classified as implementation-detail or intent-bearing. By policy, an intent-bearing auto-resolution is an escape that should have been a stop, and the closing decision digest names each one explicitly for audit. Sub-agents append heartbeats to .driver-journal.jsonl, so a dead driver is distinguishable from a slow driver. Yolo drives plan → implement → verify → review, stops before handoff, and refuses terminal-analysis workflows.

Writes: nothing of its own. The stages it drives write their artifacts; heartbeats go to .ai/workflows/<slug>/.driver-journal.jsonl.
