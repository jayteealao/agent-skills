Configuration

This page lists every configuration key the plugin honors: the per-repo .ai/sdlc-config.json, the machine-wide ~/.sdlc/hub-config.json, and the environment variables. Look up a key here when you want to change a default or find where a behavior is controlled.

Two files, zero shared fields

Configuration is split across exactly two files, and the split follows the git model. Repo-local choices live in the repository (like .git/config). Machine identity and global behavior live in your home directory (like ~/.gitconfig).

  • .ai/sdlc-config.json (per repo, committable) governs how this repository's artifacts render, how its hooks behave, and its policy choices: artifact tracking, leak guards, memory seeding.
  • ~/.sdlc/hub-config.json (per machine, never committed) governs serving and egress: how the one machine-wide hub binds, remote exposure, the code browser, and the consent gate for sending prompts to external AI services.

The two files share zero fields, so there are no precedence rules to reason about. A repo cannot set serve settings: the per-repo schema rejects view.serve. The only hub-related key a repo carries is view.hub.enabled. That key decides whether the repo participates in the hub, not how the hub runs. Both files are entirely optional. Every key has a sane default, and an absent file means all defaults.

Per-repo: .ai/sdlc-config.json

All keys are optional. The file is validated against a JSON schema (schemas/sdlc-config.schema.json) that rejects unknown properties. A key with a typo fails loudly instead of silently doing nothing.

The view block — rendering and the workflow view

view.render.concurrency4The number of artifacts that render in parallel (1–32).

view.narrativeFragmentstrueWhen true, free narrative fragments (<stem>.<label>.html.fragment siblings of raw HTML) are injected below a rendered page. Set false to suppress them repo-wide, for example while a fragment's CSS breaks a page.

view.renderQueue.maxPending500The hard backstop on pending render requests per repo. Beyond this limit, the oldest requests are evicted with a logged warning. Coalescing normally keeps the queue far below this limit.

The hooks block — write-time enforcement

Each key here switches one behavior of the installed hooks. The hooks reference describes what each hook checks and whether the hook blocks or warns. All keys default to true.

KeyDefaultWhat it does
hooks.autoStagetrueWhen true, the hook auto-stages (git add) implementation files written while an active workflow is in the implement stage.
hooks.validateOnWritetrueWhen true, workflow artifacts are validated before the write lands (filename convention, frontmatter, slug match). This check blocks.
hooks.verifyOnWritetrueWhen true, workflow artifacts get a deep schema validation after the write lands. This check blocks.
hooks.remindMissingFragmentstrueWhen true, the hook blocks a rich-tier artifact .md written without its mandatory sibling .yaml, and nudges softly when only the .html.fragment is missing. A single artifact can opt out with fragment: none in its frontmatter.
hooks.validateSiblingYamltrueWhen true, the hook validates a present sibling .yaml against its per-type schema and blocks on a violation. This check runs only for the types whose schema is reconciled to the live authoring convention (currently plan, review, design, simplify-run, ship-run).
hooks.verifyResultGatetrueWhen true, the hook hard-blocks a verify artifact whose frontmatter contradicts a passing result: result: pass with unmet metric acceptance, or with interactive-verification: deferred.
hooks.verifyDeferralLinttrueWhen true, the hook warns (non-blocking) when shadow-deferral vocabulary in a verify body ("deferred to user", "will be verified during …") co-occurs with result: pass. The check is a heuristic, so it warns rather than blocks.
hooks.mockEvidenceGatetrueWhen true, the hook hard-blocks a verify artifact that claims result: pass while at least one user-observable acceptance criterion's highest evidence rung is a mock or static analysis. Such an AC is not met. Climb the ladder or defer.
hooks.limitationClaimLinttrueWhen true, the hook warns (non-blocking) when an added comment claims a dependency capability does not exist or was removed, with no citation marker nearby. A comment is a hypothesis, not authority.
hooks.suppressionDebtLinttrueWhen true, the hook warns (non-blocking) when a new type/lint suppression (as any, @ts-ignore, eslint-disable, language equivalents) is added without an sdlc-debt: marker within two lines.
hooks.namedMechanismLinttrueWhen true, the hook warns (non-blocking) when a mechanism-suggesting noun (state machine, scheduler, queue, cache, and so on) appears in a shape or slice acceptance criterion but in no decision section of the artifact. A test may not name a machine the design does not own.
hooks.intakeLedgerLinttrueWhen true, the hook warns (non-blocking) when a default-mode intake artifact lands with neither intent-risk/charter ledger entries on the sibling 00-index.md nor the explicit none-declared escapes.

Policy and behavior keys

KeyDefaultWhat it does
artifactTrackingunset"tracked" means the .ai/ artifact tree is committed. "ignored" means the tree is gitignored except ship-plan.md and sdlc-config.json. /wf ship-plan init records the value once, so handoff and ship read a policy instead of deciding ad hoc mid-release. While the key is unset, status surfaces a one-time advisory and ship asks per run.
semantic.enabledfalseThe master switch for the two leak guards that scan outward-facing text (commit and PR messages, public-doc writes) for internal workflow vocabulary. The default is off.
semantic.mode"advisory""advisory" emits a non-blocking message that names the matched vocabulary. "enforce" denies the tool call with the same message. Promote to enforce only after the advisory false-positive rate in your repo proves near zero.
memory.seedRulestrueWhen true, each session start seeds the fenced /wf rules block into AGENTS.md, plus an @AGENTS.md import in CLAUDE.md. The plugin owns exactly the fenced region and never edits outside it. Seeding runs only in repos that have .ai/workflows/. Set false to disable seeding. Existing seeded blocks are left untouched.
solutions.globalDirnullThe absolute path to a user-level solutions corpus. Plan's reuse scan reads the corpus alongside the repo's own .ai/solutions/, and retro uses the corpus for user-confirmed lesson promotion. null disables it. The directory stays local. The plugin never syncs the directory, because repo lessons can contain project specifics.

Machine-wide: ~/.sdlc/hub-config.json

The hub is a single machine-wide process. Every singleton setting that governs how the hub binds (host, port, resource caps, remote exposure) lives here, per developer machine. The hub creates the file with defaults on its first start. A malformed file falls back to defaults. A sparse or older file is deep-merged over the defaults, so missing keys are always filled in.

KeyDefaultWhat it does
version1The config format version, stamped on every write.
host"127.0.0.1"The bind address for the hub.
port4173The canonical SDLC port. The standalone per-repo daemon falls back to 4174 only when it is forced to run alongside a live hub.
perRepoServefalseWhen false (the default), the hub is the sole server on the machine: any running per-repo daemon is reaped, none is spawned, and even a repo's own settings are overridden. Set true to allow the standalone per-repo daemon.
liveReloadtrueLive-reload for the standalone per-repo daemon. The hub itself always live-reloads.
maxSseClients200The cap on live-reload SSE clients, aggregate across repos.
maxWatchedRepos50Beyond this many registered repos, the hub polls for changes instead of using filesystem watchers.
tailscale.enabledfalseOpt-in remote access to the hub via Tailscale.
tailscale.mode"serve"The Tailscale exposure mode.
tailscale.path"/"The path prefix exposed through Tailscale.
tailscale.httpstrueWhen true, the hub serves over HTTPS through Tailscale.
tailscale.acknowledgedPublicfalseA one-time, per-machine acknowledgement that a public binding exposes every registered repo at once. This is deliberately not a committable per-repo flag.
codeBrowser.enabledtrueThe in-browser source browser served at /r/<id>/__code/.
codeBrowser.maxBlobBytes524288The text cap per file response (512 KiB).
codeBrowser.maxTreeEntries5000The per-listing truncation guard.
codeBrowser.lazyTreetrueWhen true, the code browser lists one folder per request instead of eagerly walking the tree. Listings show node_modules, so the default never walks the tree eagerly.
codeBrowser.showIgnoredBadgetrueWhen true, gitignored nodes get a badge in listings (presentation only).
codeBrowser.serveSecretsfalseWhen true, the secret denylist is dropped, so .env files and keys become servable. Keep this key false whenever the host is anything but 127.0.0.1.
codeBrowser.denyGlobs[]Extra deny patterns appended to the built-in denylist.
staleRender.healtrueWhen a served view's rendered version drifts from the running plugin (an upgrade left content behind), the hub daemon spawns a bounded background clean re-render off the request path. Set false to detect and flag only.
staleRender.maxConcurrent1The number of simultaneous heal renders across all repos.
staleRender.cooldownMs60000The per-repo minimum interval between heal attempts.
staleRender.maxAttempts3After this many attempts per drift episode, the hub gives up and surfaces failed.
externalDispatch.enabledfalseThe single machine-wide consent gate for the imagery and uiproto skills, which send prompt content to third-party AI services. The default is off: egress stays dark until a developer explicitly opts this machine in. The skill runner scripts re-check the flag themselves, so a direct script invocation cannot bypass consent. /consult is not behind this gate.

Do not change tailscale.acknowledgedPublic or codeBrowser.serveSecrets without the consequences in view. A public binding exposes every registered repo at once. codeBrowser.serveSecrets: true drops the denylist that keeps .env files unservable. Both keys default to the safe value.

Environment variables

Some environment variables adjust behavior outside either config file. The first three are kill switches for the session-start hooks. The rest supply machine state or credentials.

SDLC_DISABLE_BOOTSTRAP=1
Skips the detached background render bootstrap that the session-start hook launches. Rendering still happens on artifact writes. Only the catch-up pass at session start is suppressed.
SDLC_DISABLE_MEMORY_SEED=1
Skips the memory-seeding session-start hook entirely (the fenced /wf rules block in AGENTS.md). The per-repo equivalent is memory.seedRules: false.
SDLC_DISABLE_TRAY_HEAL=1
Skips the Windows-only reconcile of an already-running tray app after a plugin upgrade. That step would restart a tray that still executes a prior version's code.
SDLC_HOME
Relocates the entire machine-wide state directory to the given path: the registry, the hub config, and the rest of what normally lives under ~/.sdlc/.
SDLC_HUB_TOKEN
The hub's write token. The hub supervisor sets the token on the hub daemon's environment when the supervisor spawns the daemon. The token travels via env rather than argv, so it never appears in process listings. You normally never set this variable yourself.
STITCH_API_KEY, STITCH_PROJECT_ID
Credentials for the Google Stitch engine used by the internal uiproto skill. The project must be pre-created in the Stitch UI; the SDK cannot create one. When either variable is missing, uiproto's Stitch engine skips and the LLM engine is used instead, subject to the externalDispatch.enabled consent gate.
