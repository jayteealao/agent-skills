Intake modes

This page lists the thirteen ways work can enter the lifecycle through /wf intake: each mode, how the arguments resolve, what each mode authors, its branch convention, and where each mode ends.

How the arguments resolve

Intake resolves its tokens in a fixed order, and the order is user-visible. The same words mean different things when the first token names an existing workflow. The checks run in exactly this sequence:

  1. Existing slug + amend or modernize → maintenance. The two maintenance modes are claimed first. Otherwise amend would read as free scope text and modernize would read as a bare keyword. Without a real slug, both modes stop with an error; neither mode means anything standalone.
  2. Existing slug + a mode keyword → compressed slice. The run attaches as one compressed slice on that workflow. The slice file is the sole output, branch creation is suppressed, and no companion directories are written. adopt is the exception: adopt can never attach to a slug and stops here. For a closed workflow, intake asks "append a compressed slice anyway?" before it proceeds.
  3. Existing slug + free text (or nothing) → extension. No keyword is needed: an existing slug followed by new scope is the signal. The run adds full net-new slices to that workflow (see extension below). While intake reads the index, intake also notes whether the workflow predates the current schema. If the workflow predates the current schema, intake offers modernize as a first-class option before it extends.
  4. Bare mode keyword → standalone. The mode runs on its own and creates whatever workflow the mode defines. This matches the natural reading of a description that begins with a mode word ("fix the typo…").
  5. Anything else → the default flow. One twist applies: when the description strongly matches exactly one mode pattern, intake proposes that mode one time and asks. For example, a regression with an unknown cause reads as rca, and a dependency bump reads as update-deps. If you accept, the mode runs standalone. If you decline, the default flow runs. adopt, amend, and modernize are never auto-proposed.

To force the default flow when your description legitimately begins with a slug or a mode word, quote the description as one token: /wf intake "rca dashboard refresh" never matches a slug or a keyword.

An empty invocation renders the mode menu and asks.

The modes

default

/wf intake <description>

The default flow is the canonical stage 1 of 10 and the only mode with no keyword of its own. It converts a rough request into a clear intake brief through a product-owner interview. It fingerprints the stack, establishes the canonical slug, and creates the workflow. The default flow is always standalone; it is never slug-attached.

Authors: 00-index.md + 01-intake.md. Terminus: recommends /wf shape <slug>.

fix

/wf intake fix <description>
/wf intake <slug> fix <description>

fix is the quick lane for small, intentional changes with an obvious correction. Standalone, it authors the entire planning half of a standard lifecycle in one run: intake, shape, slice, and plan on a full overview index. It then stops at the pre-implement gate. The standard chain takes over from there, with the same quality gates as any other workflow. When the run is slug-attached, it becomes one compressed slice on the named workflow.

Authors: 01-fix.md → 02-shape.md → 03-slice.md → 04-plan.md. Branch: fix/<slug> (suppressed when slug-attached). Terminus: gates, then /wf implement <slug>.

hotfix

/wf intake hotfix <description>
/wf intake <slug> hotfix <description>

hotfix is the incident-response quick lane for active production emergencies. It has the same single-pass planning shape as fix, plus a hard scope lock, a diagnosis-oriented shape, and a base on the production branch. Its review stage defaults to the security dimension. When the run is slug-attached, it becomes one compressed slice on the named workflow.

Authors: 01-hotfix.md → 02-shape.md → 03-slice.md → 04-plan.md. Branch: hotfix/<slug> off the production branch (suppressed when slug-attached). Terminus: gates, then /wf implement <slug>.

refactor

/wf intake refactor <description>
/wf intake <slug> refactor <description>

refactor is the behavior-preserving quick lane. It captures a behavior baseline as the shape before any code moves. It plans incremental green steps and expects identical behavior after the change. Its review stage defaults to the refactor-safety dimension. When the run is slug-attached, it becomes one compressed slice on the named workflow.

Authors: 01-refactor.md → 02-shape.md → 03-slice.md → 04-plan.md. Branch: refactor/<slug> (opt-in; suppressed when slug-attached). Terminus: gates, then /wf implement <slug>.

update-deps

/wf intake update-deps [description]
/wf intake <slug> update-deps [description]

update-deps is the dependency-maintenance quick lane. It scans the manifests, researches each dependency, and prioritizes updates into risk tiers. Unlike the other quick lanes, it also self-authors the implement and verify stages, because its tier-ordered execution is specialized. It then routes straight to review and skips /wf implement and /wf verify. When the run is slug-attached, it becomes one compressed slice only.

Authors: 01-update-deps.md → 02-shape.md → 03-slice.md → 04-plan.md → self-authored 05-implement.md / 06-verify.md. Branch: deps/<slug>. Terminus: /wf review <slug>.

rca

/wf intake rca <symptom description>
/wf intake <slug> rca <symptom description>

rca is root-cause analysis for a reported failure whose cause is unknown. Parallel diagnosis sub-agents investigate. The result is a structured RCA with confidence, blast radius, and a suggested fix shape. The result also includes a synthesized minimal shape, so /wf plan can consume the workflow directly. rca never writes a fix. When the run is slug-attached, it becomes one compressed slice without the synthesized shape.

Authors: 01-rca.md + synthesized 02-shape.md + 00-index.md. Branch: none. Terminus: terminal — recommends /wf plan, /wf intake fix, /wf intake hotfix, or human triage.

investigate

/wf intake investigate <problem>
/wf intake <slug> investigate <problem>

investigate sketches solution options for an open design question. It enumerates every genuinely distinct candidate approach grounded in the existing architecture. Up to three approaches are presented as full cards with tradeoffs: scope, blast radius, effort, risk, and reversibility. Further distinct options are recorded compactly. The mode deliberately does not pick a winner; you pick the winner. The mode is read-only: it writes no application code and does no bug diagnosis.

Authors: 01-investigate.md + 00-index.md. Branch: none. Terminus: terminal — you pick an option, then /wf intake or /wf intake fix carries it forward.

discover

/wf intake discover <hypothesis>
/wf intake <slug> discover <hypothesis>

discover tests a hypothesis against the codebase: "is X actually the case?" Parallel sub-agents argue for the hypothesis, argue against the hypothesis, and propose counter-hypotheses. The result is a verdict of holds, partial, fails, or inconclusive, with confidence and cited evidence. The mode is read-only.

Authors: 01-discover.md + 00-index.md. Branch: none. Terminus: terminal — the next step depends on the verdict.

ideate

/wf intake ideate [area]
/wf intake <slug> ideate [area]

ideate is proactive codebase ideation. It inverts the usual direction and surfaces work you might not have thought to ask for. Parallel sub-agents scan across six lenses: quality, performance, security, DX, feature gaps, and architecture. The sub-agents generate a large candidate pool, adversarially cull the weak ideas, and rank the survivors by impact and effort. Each idea you pick seeds its own new /wf intake.

Authors: a lightweight workflow with the 01-ideate.md lead only (no build stages). Branch: none. Terminus: terminal — pick ideas, then /wf intake <idea>.

adopt

/wf intake adopt

adopt is the reverse entry. Every other mode assumes the change lies ahead. Adopt reads the change you already made in the working tree and reconstructs the planning-and-execution artifacts from what the code does. It stamps each artifact provenance: adopted, behind a confirm-before-write gate. The workflow lands at verify, so the quality tail (verify, review, handoff) runs over work done outside the pipeline. Adopt is standalone only: it can never attach to a slug, and it is never auto-proposed. It records the current branch and never creates a branch.

Authors: 01-adopt.md → 02-shape.md → 03-slice.md → 04-plan.md → 05-implement.md, all reconstructed. Branch: records the current one; never creates one. Terminus: /wf verify <slug>.

extension (keywordless)

/wf intake <existing-slug> <new scope>
/wf intake <existing-slug> from-review
/wf intake <existing-slug> from-retro

Extension is the one route with no keyword at all: an existing slug followed by free scope text is the signal. Extension adds net-new slices to that workflow, as full per-slice files, never as a compressed slice. Extension never modifies completed work. Scope corrections and follow-on work land here, because built work is never re-specified in place. The from-review and from-retro seeds pull the new scope from findings instead of free text. Extending a closed workflow is valid.

Authors: full net-new 03-slice-<new>.md file(s) plus a non-destructive master-index update. Branch: the workflow's existing one. Terminus: /wf plan <slug> <new-slice>.

amend

/wf intake <existing-slug> amend <what to change>

amend is a maintenance mode and requires a slug. Amend edits a workflow's recorded configuration in place, against a strict whitelist: branch strategy, branch, base branch, review scope, title, and tags. Amend edits nothing else. Anything outside the whitelist routes elsewhere: new scope is an extension, and wrong behavior is a fix slice. Amend writes no numbered artifact, writes no slice, and never touches built work.

Authors: edits to 00-index.md and the registry row only. Branch: n/a. Terminus: whatever the workflow was already doing.

modernize

/wf intake <existing-slug> modernize

modernize is a maintenance mode and requires a slug. Modernize backfills an older workflow's artifacts to the schema the installed plugin now expects: charter, intent-risk ledger, wall-ownership and clearing-event fields on deferrals, and revision ledgers. Modernize is strictly additive: it fills absent fields from what the artifacts already say, and it never rewrites a recorded decision, verdict, or acceptance criterion. Intake also detects schema drift automatically when you extend an old workflow, and it offers modernize then.

Authors: additive field backfill across the workflow's existing artifacts. Branch: n/a. Terminus: the command that resolves the largest remaining gap.

Runtime verification (/wf probe) and read-only triage (/wf simplify) are not intake modes. They act on already-built or existing code, so they are top-level keys of their own.
